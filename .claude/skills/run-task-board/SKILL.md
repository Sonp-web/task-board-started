Доска задач — клиентское Vite + React приложение без бэкенда (данные в
`localStorage`). Агент поднимает dev-сервер и управляет страницей через
`.claude/skills/run-task-board/driver.mjs` — драйвер без зависимостей,
который запускает headless Chrome и читает команды из stdin.

Все пути — от корня репозитория.

## Требования

- Node.js 22+ (драйверу нужен встроенный `WebSocket`; проверено на 24.12).
- Установленный Google Chrome или Chromium. Если он лежит не в стандартном
  месте — задайте `CHROME_PATH`.

## Установка

```bash
npm ci
```

## Запуск (путь агента)

1. Поднять dev-сервер в фоне и дождаться порта:

```bash
(npm run dev > /tmp/task-board-dev.log 2>&1 &)
for i in $(seq 1 30); do curl -sf http://localhost:5173 >/dev/null && break; sleep 1; done
```

2. Передать сценарий драйверу. Одна команда на строку; на первой же ошибке
   драйвер останавливается и выходит с кодом 1.

```bash
node .claude/skills/run-task-board/driver.mjs <<'EOF'
theme light
nav http://localhost:5173
wait Командная доска
click Новая задача
fill Название = Проверка драйвера
fill Описание = Создано через driver.mjs
fill Приоритет = Высокий
fill Срок = 2020-01-15
click Создать
gone Приоритет
click Переместить: Проверка драйвера
text section[aria-label="Статистика доски"]
ss board
errors
EOF
```

Ожидаемо: статистика `Всего задач: 7 / В работе: 3 / Готово: 2 /
Просрочено: 4`, строка `screenshot: <путь>/board.png` и `no page errors`.
**Откройте скриншот и посмотрите на него.**

3. Остановить сервер:

```bash
lsof -ti:5173 -sTCP:LISTEN | xargs kill
```

Скриншоты пишутся в `$SHOTS_DIR` (по умолчанию `$TMPDIR/task-board-shots`);
точный путь драйвер печатает сам.

| команда | что делает |
|---|---|
| `nav <url>` | открыть страницу и дождаться загрузки |
| `wait <текст>` / `gone <текст>` | дождаться появления / исчезновения текста |
| `click <имя>` | настоящий клик мышью по кнопке с таким `aria-label` или текстом |
| `fill <метка> = <значение>` | поле формы под `<label>`; для select — текст опции, для даты — `YYYY-MM-DD`, пусто — очистить |
| `press <Enter\|Escape\|Tab>` | нажатие клавиши |
| `text [css]` | напечатать `innerText` страницы или элемента |
| `eval <js>` | выполнить выражение в странице |
| `storage` | напечатать задачи из `localStorage` |
| `theme <dark\|light>` | эмулировать `prefers-color-scheme` |
| `size <ш> <в>` | размер вьюпорта (по умолчанию 1280×800; мобильный — `size 390 844`) |
| `ss [имя]` | скриншот всей страницы |
| `errors` | упасть, если в консоли были ошибки или исключения |

Имена кнопок: в шапке — `Новая задача`, `Восстановить пример`; на карточке —
`Редактировать: <название>`, `Переместить: <название>`, `Удалить: <название>`;
в диалогах — `Создать`, `Сохранить`, `Отмена`, `Удалить задачу`,
`Восстановить задачи`. Колонки — `section[aria-label="Запланировано"]`,
`"В работе"`, `"Готово"`.

## Production-сборка

Нужна, когда поведение отличается от dev (см. «Подводные камни» про StrictMode):

```bash
npm run build
(npx vite preview > /tmp/task-board-preview.log 2>&1 &)
for i in $(seq 1 30); do curl -sf http://localhost:4173 >/dev/null && break; sleep 1; done
node .claude/skills/run-task-board/driver.mjs <<'EOF'
nav http://localhost:4173
wait Командная доска
eval localStorage.setItem('redev-task-board:v1', '{broken')
nav http://localhost:4173
wait Сохранённые данные были повреждены
ss recovered
errors
EOF
lsof -ti:4173 -sTCP:LISTEN | xargs kill
```

```bash
npm run dev   # откройте http://localhost:5173, остановка — Ctrl-C
```

## Подводные камни

- **Каждый запуск драйвера — чистый профиль Chrome.** `localStorage` пуст,
  доска всегда стартует с сид-данных (6 задач). Весь сценарий, которому нужно
  общее состояние, должен идти в одном heredoc.
- **Плашка «Сохранённые данные были повреждены» не появляется в dev.**
  `StrictMode` дважды запускает эффект загрузки: первый `load()` чинит
  хранилище, а его результат отбрасывается, второй видит уже целые данные и
  возвращает `recovered: false`. Проверяйте восстановление на `vite preview`.
- **Тема по умолчанию берётся из системы.** На macOS с тёмным оформлением
  headless Chrome рисует тёмную тему. Для воспроизводимых скриншотов первой
  строкой ставьте `theme light` или `theme dark`.
- **«Просрочено» зависит от сегодняшней даты.** Сроки в сиде — сентябрь 2026,
  поэтому сейчас их три просроченных; не сверяйте это число с константой из
  старого прогона.
- **Пока открыт диалог, `click` ищет только внутри него** — остальная страница
  инертна из-за `showModal()`. Закройте диалог (`click Отмена` или
  `press Escape`), прежде чем кликать по доске.
- **После отправки формы ждите `gone Приоритет`**, а не появления названия:
  название есть в поле ввода ещё до сохранения, и `wait` сработает раньше.
- **Не присваивайте `el.value` через `eval`** — React этого не увидит.
  Используйте `fill`.
- **README устарел в текстах интерфейса:** колонка называется «Запланировано»,
  а не «К выполнению», кнопка сброса — «Восстановить пример», а не «Сбросить
  данные».
- **На скриншоте с открытым диалогом затемнение не доходит до низа** — фон
  диалога покрывает вьюпорт, а `ss` снимает страницу целиком. Это артефакт
  съёмки, не баг вёрстки.

## Диагностика

- **`timeout: command not found`** — на macOS нет GNU `timeout`; ждите порт
  циклом `for … curl … sleep 1`, как выше.
- **`net::ERR_CONNECTION_REFUSED (is the dev server running?)`** — сервер не
  поднят или порт другой. Если 5173 занят, Vite молча берёт следующий порт —
  смотрите адрес в `/tmp/task-board-dev.log`.
- **`button not found: …`** — имя не совпало с `aria-label`/текстом кнопки
  либо открыт диалог, перекрывающий доску. Выведите `text` и сверьте.
- **`Chrome not found: set CHROME_PATH …`** — укажите путь к бинарнику Chrome.
